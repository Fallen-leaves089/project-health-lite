# 普通用户报告格式

> 英文用户按同样结构翻译标题和正文；代码、路径、命令保持原文。

## 结构

```markdown
# 项目体检结果

- 检查范围：完整项目 / 本次改动 / 无 Git 快照

## 结论

先修再上线

一句话：项目能跑起来，但有 1 个问题可能让上线失败，2 个问题建议在交付前处理。

## 先做最重要的 1-3 件事

1. 先修数据库迁移入口，否则新环境可能直接起不来。
2. 把示例配置里的默认密码换成占位符，并让启动时拒绝默认值。
3. 用空数据库跑一次启动流程，确认新环境能完成部署。

## 会卡住上线

### 1. 数据库迁移没有执行入口

- 哪里：`deploy/start.ps1:18`
- 证据：已验证（启动脚本中没有迁移步骤，部署配置也没有其他入口）
- 为什么：启动脚本只启动了服务，没有执行数据库迁移；新环境可能因为缺表直接报错。
- 下一步：在部署流程里补迁移命令，并用空数据库跑一次。

## 最好先修

### 1. 示例配置里有默认密码

- 哪里：`.env.example:7`
- 证据：已验证（示例配置中直接写入了默认密码）
- 为什么：默认值容易被直接带到线上。
- 下一步：改成明显的占位符，并在启动时拒绝空值或默认值。

## 可以以后再说

### 1. README 缺少本地启动说明

- 哪里：`README.md`
- 证据：已验证（README 中没有安装、启动和验证命令）
- 为什么：不影响当前运行，但会增加交接成本。
- 下一步：补三条命令：安装、启动、验证。

## 如果没有发现明显问题

当前没有发现会卡住上线的问题，但不要把“本轮没发现”写成“绝对安全”。仍然列出没检查到的部分，并说明下一步建议运行的测试或构建。

## 我没检查到的部分

- 没有运行测试和构建，所以不能判断运行时错误。
- 没有检查生产环境、数据库真实数据和第三方服务配置。
- 没有做安全审计或渗透测试。

## 你可以接着做什么

- 想修哪一条，直接说“帮我修第 1 条”。
- 想继续深入，说“跑一次测试”或“做一次交接检查”。
```

有发现时保留三档和行动清单；没有明显发现时，省略三档和行动清单，只保留“结论 / 如果没有发现明显问题 / 我没检查到的部分”，不要为了凑格式硬塞问题或行动项。

## 语气要求

- 先说人话，再给证据。
- 不把高风险写成“建议关注”。
- 不把不确定写成确定。
- 每条结论必须带证据行，并标清状态：`已验证`（有文件位置或命令结果）、`推断`（合理怀疑但未证）、`未检查`（没覆盖到）。
- 不用“绝对安全”“零风险”“全球最强”等承诺。
- 第一次出现术语时解释，例如“CI 就是每次提交后自动跑检查的流程”。

## 敏感信息

只写位置和类型，例如：

```text
- 哪里：`config/local.json:12`
- 为什么：这里有一个疑似数据库密码的明文值，具体内容已隐藏。
```

不要复制密钥、令牌、Cookie、私钥、完整连接串或生产地址。

不要根据值的字样判断它是占位符、真实凭据还是仍然有效；无法确认时只写“疑似”，并建议轮换或核实。
